## Descrição do Projeto

No terceiro semestre o time desenvolveu um **Sistema de Registro de Movimentações** voltado para a gestão de controle de acesso de colaboradores terceirizados. A aplicação foi concebida em parceria com a empresa **Altave**, para automatizar o controle de acesso de colaboradores terceirizados em zonas de manutenção naval. O desafio era substituir o controle manual analógico por uma plataforma digital inteligente, conteinerizada e capaz de exportar análises gerenciais seguras de fluxo e frequência de funcionários

## [Repositorio do projeto](https://github.com/SQLutions-FATEC/API-3-Semestre)

## Contribuição para o Projeto

Com foco de atuação direcionado à camada de **Front-end**, assumi a responsabilidade pelo desenvolvimento de módulos críticos da interface, garantindo a comunicação fluida com os serviços de *back-end*. Minhas principais contribuições incluíram:
Desenvolvi todo o módulo de cadastro e a Tabela Dinâmica de Registros, onde o grande desafio foi receber dados brutos e timestamps do servidor e formatá-los para uma exibição intuitiva para o usuário final, acoplando a funcionalidade de edição de usuários direto da tabela via chamadas HTTP.

O momento de maior complexidade técnica, no entanto, foi o desenvolvimento do Subsistema de Exportação em Lote (.csv). ### Em 2025-2 (Sistema de Mobilidade Urbana)

## Descrição do Projeto

O desafio do quarto semestre consistiu no desenvolvimento de uma **Plataforma de Inteligência de Dados Orientada à Mobilidade Urbana**, voltada para o monitoramento de radares e fluxo viário do município de São José dos Campos. O sistema realiza a ingestão e a análise de grandes volumes de dados de telemetria urbana, transformando registros brutos de tráfego em _dashboards_ interativos e indicadores gerenciais estratégicos. O produto foi projetado para atender tanto às demandas operacionais de gestores públicos da **Prefeitura de São José dos Campos** quanto às necessidades de consulta informativa do cidadão comum.   

## [Repositorio do projeto](https://github.com/SQLutions-FATEC/API-4-Semestre)

## Contribuição para o Projeto

Com atuação focada nas frentes de **Front-end** e **UI/UX Design**, fui responsável pela concepção da experiência do usuário, estruturação do visual do site e desenvolvimento de mecanismos de integração da interface.

Durante o projeto, percebi que o maior desafio no front-end seria exibir uma alta densidade de dados de forma fluida sem poluir a tela com alta quantidade de informações. Para garantir que a nossa equipe não ficasse paralisada aguardando o back-end finalizar a ingestão e integração dados dos radares ao banco, projetei e implementei uma Camada de Simulação (Mock) no código. Espelhei os contratos de banco de dados na nossa aplicação Vue.js, permitindo o desenvolvimento e teste das interfaces do frontend.

Outro ponto seria que nosso time não possuía um modelo a ser seguido ao desenvolver o frontend, logo tomei frente e decidi construir um wireframe, garantindo a consistencia da interfface em todos os componentes e o fluxo de experiencia do usuário, precisei entender como aplicar as funcionalidades do projeto a uma tela real do zero, isso me fez entender muito mais a fundo sobre o projeto do que os semestres anteriores, pois era necessário não só imaginação mas muita criatividade na hora de portar as User stories para o wireframe.

### Em 2026-1 (Synthesi)

## Descrição do Projeto
No quinto semestre, nosso time desenvolveu o **Synthesi**, uma plataforma de inteligência voltada para a gestão de projetos. O grande desafio apresentado pelo cliente era a ineficiência na análise de dados, que estavam dispersos em diversas planilhas manuais. Nossa missão foi centralizar essas informações utilizando conceitos de *Data Warehouse*, automatizando a geração de indicadores e *dashboards* para que os gestores ganhassem tempo e produtividade na tomada de decisão.

Para isso, construímos uma aplicação *web* hospedada na nuvem (AWS). O sistema contava com rotinas automatizadas de ETL (Extração, Transformação e Carga) que processavam as planilhas do cliente e alimentavam um banco de dados modelado no formato *Snowflake*. Essa arquitetura garantiu agilidade para renderizar *dashboards* complexos sobre acompanhamento de horas, orçamento (horas vs. materiais), controle de estoque e análise de fornecedores.

## [Repositorio do projeto](https://github.com/SQLutions-FATEC/API-5-Semestre)

### Contribuições Pessoais
Neste semestre, tomei uma decisão que me tirou completamente da zona de conforto: assumi o papel de *Product Owner* (PO). Nos projetos anteriores eu já auxiliava na estruturação de tarefas, mas agora o desafio era muito maior: traduzir a dor real do cliente em um produto funcional. No início, foi a fase mais difícil do curso, pois precisei mudar minha mentalidade de desenvolvedor — que costuma seguir tarefas já estruturadas — para a visão estratégica de quem define *o que* precisa ser feito e *por que*.

Minha principal contribuição foi guiar a direção do Synthesi para maximizar a entrega de valor. Conduzi o levantamento de requisitos, validei *wireframes* diretamente com o cliente e desmembrei o problema em histórias de usuário claras, priorizando o *backlog* das *sprints* de forma estratégica. Além da gestão, atuei fortemente na base técnica do produto: modelei a lógica inicial do *Data Warehouse*, defini as fórmulas dos indicadores financeiros e documentei toda a estrutura do repositório principal.

Como o projeto exigia uma aplicação prática de DevOps, também assumi a frente de **Monitoramento e Infraestrutura**. Configurei o Prometheus e o Grafana para monitorar a saúde do banco de dados e conduzi testes de estresse para descobrir os limites da aplicação. A partir dessas métricas, elaborei um plano de escalonamento real, traçando metas de capacidade de usuários e projetando os custos de infraestrutura em nuvem necessários para cada fase de crescimento do sistema.
